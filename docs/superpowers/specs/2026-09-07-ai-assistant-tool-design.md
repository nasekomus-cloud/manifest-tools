# Инструмент «AI-ассистент»: дизайн

Статус: одобрено пользователем в чате 2026-09-07, ожидает разбивки на план реализации.

## Зачем

Пользователь хочет добавить на сайт инструмент, где можно загрузить любые
файлы, задать любой вопрос или задачу, и получить в ответ не только текст, но
и сгенерированные файлы (например, «переделай этот Excel и верни новый
файл»). В отличие от остальных инструментов сайта (`merge/`, `dg-check/`,
`dashboard/` и т.д.), которые целиком работают в браузере без сервера, этот
инструмент принципиально требует сервера: авторизацию Claude нельзя положить
в клиентский JS, а генерация произвольных файлов по произвольной задаче
требует реального выполнения кода, а не фиксированной логики.

Пользователь явно указал: работать должно **через личную подписку Claude
(Pro/Max)**, не через оплату по API-токенам. Это определяет выбор SDK: не
Claude API (Messages API), а **Claude Agent SDK** — тот же движок, что у
Claude Code, который умеет авторизоваться через `ant auth login` учётной
записью подписки вместо API-ключа.

## Смена хостинга (предпосылка)

Сайт сейчас — статика на GitHub Pages, без сервера. Для этого инструмента
нужен сервер, поэтому весь сайт переезжает на VPS пользователя:

- Nginx как reverse-proxy перед Node.js-приложением, TLS через Let's Encrypt
  на домен, который предоставит пользователь.
- **HTTP Basic Auth на уровне Nginx** (`.htpasswd`, один общий логин/пароль)
  защищает весь сайт целиком — решение пользователя (не только страницу
  нового инструмента). Реализуется полностью в конфиге Nginx, без кода
  приложения — самый маленький и надёжный вариант для этой задачи.
- Все существующие инструменты (`merge/`, `dg-check/`, `dashboard/`,
  `dashboard-departure/`, `bl-split/`, `grand-total/`) переносятся как есть —
  их логика не меняется, меняется только то, что раздаёт файлы Node/Express
  вместо GitHub Pages.

## Почему Docker-изоляция обязательна

Claude Agent SDK — это Claude Code как библиотека: у него **настоящий
доступ к bash и файловой системе** там, где он запущен (в отличие от Claude
API, где выполнение кода шло бы в песочнице на стороне Anthropic). Раз
посетитель сайта может «поставить любую задачу», Claude по этой задаче будет
на самом деле выполнять команды на сервере. Без изоляции это прямой риск для
VPS (случайное или намеренное разрушительное действие, утечка данных других
инструментов сайта, если они окажутся в поле зрения).

Пользователь подтвердил: каждая сессия инструмента выполняется в отдельном
одноразовом Docker-контейнере.

## Архитектура

```
Браузер посетителя
   │  HTTPS (Basic Auth от Nginx)
   ▼
Nginx (TLS, .htpasswd) ──────────────► статика: index.html, merge/, dg-check/,
   │                                    dashboard/, dashboard-departure/,
   │                                    bl-split/, grand-total/, assistant/
   ▼
Node.js/Express (systemd-сервис)
   │
   ├─ статика — как раньше, без изменений в её коде
   │
   └─ /api/assistant/*  ── очередь на 1 активную сессию одновременно
          │
          ▼
     Docker-контейнер (создаётся на сессию, --network none, лимиты CPU/RAM,
     жёсткий тайм-аут)
          │
          ├─ /workspace/input/  — загруженные пользователем файлы
          ├─ /workspace/output/ — файлы, которые Claude решит создать
          ├─ Claude Agent SDK (Node), read-only volume с профилем
          │   подписки (`ant auth login`, выполняется один раз на VPS,
          │   не в контейнере)
          └─ встроенные инструменты Agent SDK: Read/Write/Edit/Bash/Glob/Grep
             (WebSearch/WebFetch не нужны и не должны быть доступны — сеть
             отключена)
```

## Компоненты

### 1. Nginx + TLS + Basic Auth
- Один `.htpasswd` с общим логином/паролем на весь сайт.
- Домен и DNS — со стороны пользователя; сертификат — certbot на VPS.

### 2. Express-приложение
- Раздаёт существующие статические файлы без изменений в их логике.
- Новая папка `assistant/` (по образцу остальных инструментов):
  `index.html`, `app.js` — drag-and-drop зона для любых файлов + текстовое
  поле задачи + область истории переписки. Добавляется строкой в `tools.js`,
  как и любой другой инструмент.
- `POST /api/assistant/message` — принимает multipart (текст задачи + файлы),
  ставит в очередь (см. ниже), возвращает поток событий (SSE) с текстом
  ответа по мере готовности и списком сгенерированных файлов в конце.
- `GET /api/assistant/files/:id` — отдаёт сгенерированный файл на скачивание;
  файлы живут ограниченное время (например, 1 час) и потом удаляются с диска.
- История переписки на сервере держится в памяти процесса, на сессию (по
  `session_id`, который браузер хранит в `localStorage` и присылает с каждым
  запросом). Не персистится на диск — при перезапуске сервера история
  обнуляется. Это осознанное упрощение: инструмент не рассчитан на
  многодневные разговоры, только на разовую задачу в один присест.

### 3. Очередь на одну сессию
- Раз сервер работает под личной подпиской пользователя (тем же аккаунтом,
  которым пользуются на claude.ai лично), нельзя допускать, чтобы несколько
  посетителей сайта параллельно ели лимит подписки одновременно.
- Простая очередь в памяти процесса: если сессия уже выполняется, новый
  запрос ждёт (с сообщением на странице «инструмент занят, подождите»)
  вместо параллельного запуска.

### 4. Контейнер на сессию
- Образ на базе `node:XX-slim` (версия Node фиксируется при реализации) с
  предустановленным Claude Agent SDK.
- `docker run --network none --memory=<лимит> --cpus=<лимит> --rm`, с
  read-only volume с профилем `ant auth login` и рабочим volume с
  input/output файлами конкретной сессии.
- Жёсткий тайм-аут на весь запуск (например, 5 минут) — по истечении
  контейнер принудительно останавливается и удаляется, пользователю
  возвращается ошибка тайм-аута.
- После завершения: файлы из `/workspace/output/` копируются в область
  скачивания на хосте, контейнер удаляется (`--rm` делает это автоматически).

### 5. Авторизация подписки
- `ant auth login` выполняется один раз вручную на VPS (интерактивный вход
  через браузер учётной записью Pro/Max пользователя).
- Полученный профиль сохраняется в volume, который монтируется **только на
  чтение** в каждый сессионный контейнер — учётные данные не копируются и не
  размножаются.
- Если подписка когда-то потребует повторного входа (истёкший токен) —
  сессии начнут падать с ошибкой авторизации; это отражается в логах сервиса,
  почему-то не в объёме этого дизайна (это операционный вопрос обслуживания,
  не отдельная фича).

## Данные и их время жизни

| Данные | Где хранятся | Время жизни |
|---|---|---|
| Пароль Basic Auth | `.htpasswd` на VPS | Постоянно, меняется вручную |
| Профиль подписки | Docker volume, read-only в контейнерах | Постоянно, до повторного `ant auth login` |
| Входные файлы сессии | Volume контейнера | Удаляются вместе с контейнером после сессии |
| Сгенерированные файлы | Каталог на хосте, отдаётся по `/api/assistant/files/:id` | TTL (например, 1 час) или до скачивания — уточняется при реализации |
| История переписки | Память процесса Express, по `session_id` | До перезапуска сервера |

## Обработка ошибок

- Тайм-аут контейнера — понятное сообщение пользователю, а не зависшая
  страница.
- Ошибка авторизации подписки (истёкший `ant auth login`) — отдельное
  сообщение, отличимое от обычной ошибки задачи.
- Сессия уже выполняется (очередь) — статус «занято», а не тихое зависание.
- Файл на скачивание уже удалён (TTL истёк) — понятная ошибка 404 с
  объяснением, а не пустой ответ.

## Тестирование

- Юнит-тесты (в стиле остальных инструментов, `node --test`) — там, где есть
  чистая логика без Docker/сети: разбор multipart-запроса, формирование
  списка файлов на скачивание, логика очереди (одна активная сессия),
  TTL-очистка файлов.
- Docker-оркестрация и сам вызов Agent SDK — тестируются вручную (нельзя
  осмысленно замокать без потери смысла проверки) на реальном VPS с реальной
  подпиской при вводе в строй.

## Открытые технические вопросы (уточняются при реализации, не сейчас)

Это не пробелы в дизайне, а места, где точные параметры API нельзя было
надёжно вспомнить без документации на момент проектирования — фиксируются
здесь, чтобы не потерять, и закрываются чтением актуальной документации
Claude Agent SDK перед написанием соответствующего кода:

- Точное имя npm-пакета и способ вызова Claude Agent SDK в безголовом режиме
  (без интерактивных подтверждений инструментов).
- Как именно SDK внутри контейнера подхватывает профиль `ant auth login`,
  смонтированный томом (переменные окружения / путь конфигурации).
- Формат событий потока (SSE) от Agent SDK — что стримить на страницу по
  мере выполнения задачи, а что показывать только по завершении.

## Вне рамок этого дизайна

- Персистентная история переписки между визитами (сознательно не нужна для
  первой версии).
- Многопользовательский доступ с разными паролями/ролями — общий Basic Auth
  на весь сайт достаточен для двух пользователей.
- Доступ инструмента к интернету (WebSearch/WebFetch) — сеть контейнера
  отключена полностью; если в будущем понадобится браузинг для задачи, это
  отдельное решение с отдельной оценкой рисков.

# Границы — от спецификации к коду

Ярус **T0** — один инструмент, без внешних сервисов, собирается в один проход,
без разбивки на таски. Этот файл существует и на T0: следующая сессия (и Phase 9)
читает именно его, а не восстанавливает границы заново.

## Проектные правила

- Стек — тот же, что и везде на сайте: ES-модули без сборки, ExcelJS с CDN (`4.4.0`) в браузере / из `devDependencies` в тестах, JSZip с CDN (`3.10.1`, та же версия, что уже используется в `bl-split/index.html`) — новую версию не заводить.
- Тесты — `node --test` (команда `npm test`); `core.js` не импортирует ни ExcelJS, ни JSZip сам — принимает готовые объекты снаружи (см. spec «Решения по реализации» §2).
- Кэш GitHub Pages — 10 минут на `.js`: при каждой правке `core.js`/`app.js`/`tools.js`/`index.html` (главной) обновить `?v=<YYYYMMDDHHMM>` во всех местах, где встречается ссылка на файл (см. CLAUDE.md, раздел «Подводные камни», последний пункт).
- Отсутствующая зависимость — это `BLOCKED`, а не повод её ставить/апгрейдить самому.
- Не трогать: `merge/`, `dg-check/`, `dashboard/`, `dashboard-departure/`, `bl-split/`, `grand-total/`, `lib/*` — существующие инструменты, общие модули и их тесты. Новый инструмент — отдельный каталог `order-check/`, ничего общего с этими каталогами не переиспользует, кроме констант `lib/manifest-format.js` (`SHEET_NAME`, `COLUMN_HEADER_ROW`, `DATA_START_ROW`, `FIRST_COLUMN`, `LAST_COLUMN`) — только чтение, без правок самого файла.

## Границы, решённые в спецификации

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `order-check/core.js` | логикой сверки: группировка строк поручения, сопоставление контейнер↔поручение, правила веса/пломб/типа/опасных грузов, построение столбца и заливки | `crossCheckOrders(combinedWb, orderEntries) -> {ok, resultWorkbook, summary} \| {ok:false, error}` | поиск колонок (свода и поручений), группировку многострочных контейнеров, карту ISO→футность, разбор опасных грузов, сравнение пломб как множеств |
| `order-check/app.js` | состояние страницы: выбор/разбор файлов (включая распаковку zip через JSZip), вызов `core.js`, рендер сводки и предупреждений, скачивание результата | — (обычный DOM-скрипт, без публичного API) | — |

Формы возвращаемых значений, ключевые слова поиска колонок, правило группировки строк, правило исключения «поддоны»/«палеты», допуск сравнения весов — см. «Решения по реализации» в `spec.md`, раздел скопирован сюда дословно по сути, без повтора текста.

## Швы для тестов

- `crossCheckOrders` (`order-check/core.test.js`) — единственный шов этого инструмента; поведение проверяется только через него.
- `app.js` тестами не покрывается — чистый DOM, как и другие `app.js` на сайте.

## Построено (T0, один проход)

- `order-check/core.js` — `crossCheckOrders(combinedWb, orderEntries) -> {ok, resultWorkbook, summary, warnings} | {ok:false, error}`. Формы и правила — как в спецификации, без изменений: группировка многострочных контейнеров поручения, исключение строк «поддоны»/«палеты»/их вариантов (точное совпадение, не подстрока) из веса груза, карта ISO→футность на лету по большинству, сопоставление контейнер↔поручение по паре ключей с откатом на поиск по одному контейнеру, сравнение пломб и опасных грузов как множеств.
- 18 тестов в `order-check/core.test.js` — по одному на каждое значимое поведение из спецификации (совпадение/расхождение по каждому полю, «поддоны» vs «палеты» vs похожее по названию не-поддонное грузовое место, перенос строки в номере поручения, контейнер под чужим/никаким поручением, несколько файлов, битый файл поручения, отсутствующий лист «Manifest»).
- `order-check/app.js` — DOM: два дропзоны (сводный файл — один `.xlsx`; поручения — `.zip` через JSZip и/или несколько `.xlsx` вперемешку, служебные записи архива `__MACOSX/`/`.DS_Store`/каталоги молча пропускаются), кнопка «Сверить», список предупреждений о нечитаемых файлах, сводка на странице, кнопка «Скачать».
- `order-check/index.html` — по образцу `dg-check`, ExcelJS `4.4.0` + JSZip `3.10.1` (та же версия, что в `bl-split`) с cdnjs.
- `tools.js` — новая карточка «Сверить с поручениями на погрузку»; `index.html` (главная) — версия `tools.js?v=` обновлена на `202609101357`.
- **Проверено на реальных данных пользователя** (сводный файл на 673 строки + 3 реальных поручения, включая известный случай с пропущенными UN-номерами опасного груза у контейнера NYKU3205488) — и через `core.js` напрямую, и через полный путь в браузере (drag-and-drop эмулирован программно: `DataTransfer` + `change`, т.к. инструмент автоматизации браузера не даёт нативно выбрать файл в `<input type=file>`): результат совпал с найденным ранее вручную. Разбор ExcelJS в песочнице браузера инструмента автоматизации оказался медленным (секунды на файл вместо миллисекунд в Node) — это особенность песочницы (тот же эффект показал и уже существующий `dg-check` на том же файле), не дефект кода.

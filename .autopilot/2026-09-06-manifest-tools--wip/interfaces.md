# interfaces.md

## Проектные правила

- **Стек:** чистые HTML/CSS/JS (ES-модули), без сборки, без bundler. Единственная
  сторонняя библиотека в самом сайте — **ExcelJS**, подключается в браузере как
  классический `<script src="https://cdnjs.cloudflare.com/.../exceljs.min.js">`
  (глобальная переменная `ExcelJS`), версию зафиксировать в теге явно.
- **Тесты — на Node**, через встроенный `node --test` (без сторонних тест-раннеров).
  Для тестов нужен пакет `exceljs` из npm как devDependency (`npm install` один раз
  перед первым запуском тестов) — это не влияет на сам сайт, который остаётся
  статикой без npm-зависимостей в проде.
- **Запуск локально:** открыть `index.html` в браузере (или `python3 -m http.server`
  из корня и зайти на `localhost:PORT`) — сайт статический, сервер не обязателен.
- **`core.js` каждого инструмента не имеет собственных импортов** — принимает уже
  готовые объекты `ExcelJS.Workbook` и примитивы, ничего не требует и не подключает
  сам. Это то, что позволяет одному и тому же файлу работать и в браузере (workbook
  создан через глобальный `ExcelJS`), и в тесте на Node (workbook создан через
  `import('exceljs')`).
- **Отсутствующая зависимость возвращается как `BLOCKED`**, а не устанавливается
  произвольно поверх того, что решено здесь — если версии ExcelJS с CDN не хватает
  какой-то функции стилей, это блокер тикета, а не повод менять стек.
- Ничего в проекте на момент старта тикетов ещё не существует — трогать нечего,
  зон конфликта с уже написанным кодом нет.

## Границы, решённые в спецификации

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `lib/manifest-format.js` | описание формата манифеста (лист, строки, колонки) | `validateStructure(workbooks) -> {ok, error?}` | номера строк/букв колонок как внутренние константы |
| `merge/core.js` | логика склейки | `mergeManifests(workbooks, {renumber}) -> {resultWorkbook, summary}` | построчное копирование стилей, пересчёт нумерации |
| `dg-check/core.js` | логика сверки | `crossCheckDangerousGoods(combinedWb, dgWb) -> {resultWorkbook, summary}` | поиск колонок по заголовку, группировку по контейнеру, правила подсветки |
| `app.js` (в каждом инструменте) | состояние страницы (выбранные файлы, порядок, чекбоксы) | — (точка входа, ничего не выставляет наружу) | работу с `<input type=file>`, drag-and-drop, скачивание блоба |
| `tools.js` | список карточек главной страницы | массив `{title, description, href}` | — |

Швы для тестов: `validateStructure`, `mergeManifests`, `crossCheckDangerousGoods` —
чистые функции от книг ExcelJS и примитивов, без DOM и без сети.

## Что построили тикеты (растёт по ходу сборки)

### 01 — Каркас и формат манифеста

- `lib/manifest-format.js` — ES-модуль, экспортирует `validateStructure(workbooks)`.
  Вход: `Array<{fileName: string, workbook: ExcelJS.Workbook}>` (пары имя+книга,
  не просто книги — имя нужно для сообщений об ошибке). Возвращает `{ok: true}`
  либо `{ok: false, error: string}` с именем файла и адресом первой несовпавшей
  ячейки (`H5` и т.п.) либо с указанием отсутствующего листа `Manifest`.
  Также экспортирует константы `SHEET_NAME`, `HEADER_FIRST_ROW`, `COLUMN_HEADER_ROW`,
  `DATA_START_ROW`, `FIRST_COLUMN` (3=C), `LAST_COLUMN` (25=Y) — можно переиспользовать
  в `merge/core.js` и `dg-check/core.js`, чтобы не дублировать номера строк/колонок.
- **Поправка (от оркестратора, после тикета 01):** в тикете 01 ошибочно было
  написано требование «открывается двойным кликом / `file://`». Это не так —
  реальное решение (брифинг, R18i): сайт публикуется на **GitHub Pages**, то есть
  всегда открывается по `https://`, где никаких CORS-ограничений на
  `<script type="module">` нет. `index.html`/`tools.js` тикета 01 остались на
  обычных скриптах (`window.TOOLS`) — это не ошибка, так тоже работает и на
  GitHub Pages, трогать не нужно. **Но для тикетов 02 и 03 ограничение по
  `file://` не действует** — `merge/app.js` и `dg-check/app.js` можно (и нужно,
  для единообразия с `core.js`/тестами на Node) подключать как
  `<script type="module">` и использовать обычный `import` из `core.js` и
  `lib/manifest-format.js`, без обходных приёмов.

### 02 — Объединить манифесты

- `merge/core.js` экспортирует `mergeManifests(workbooks, {renumber=false}) ->
  {resultWorkbook, summary: {files: Array<{fileName, rows}>, totalRows}}`.
  Бросает `Error(message)` при несовпадении структуры (переиспользует
  `validateStructure` и её текст ошибки) или при пустом списке файлов —
  `app.js` ловит и показывает как ошибку на странице, ничего не создаёт.
  Копирует колонки `A:Y` целиком (не только `C:Y` из формата) — колонка A это
  «№п/п», нужна для истории 8 (сквозная нумерация). Шапка (строки 1–5,
  включая объединения ячеек через `worksheet.model.merges`) берётся из первого
  файла в списке.

### 03 — Сверить опасные грузы

- `dg-check/core.js` экспортирует `crossCheckDangerousGoods(combinedWb, dgWb) ->
  {ok:true, resultWorkbook, summary:{mismatchCount, notFoundInSummaryCount}} |
  {ok:false, error}`. Новый столбец пишется в `LAST_COLUMN+1` (после `Y`, то
  есть `Z`) сводного файла — использует те же константы из
  `lib/manifest-format.js`, что и `merge/core.js`. В DG-манифесте лист и
  расположение заголовков не фиксированы — заголовки колонок (контейнер/UN/
  класс) ищутся по ключевым словам в первом листе, без привязки к номеру
  строки/буквам столбца.

# Спецификация: редизайн сайта — вариант Б «Лоция»

## Задача

Сайтом каждый день пользуются для работы с манифестами. Инструментов уже восемь, а
переход между ними всё ещё идёт через главную, по одной карточке. На странице
инструмента непонятно, куда смотреть: «Выбрать файлы» и главная кнопка выглядят
одинаково, зона для файлов почти не видна на белом фоне, итог обработки оказывается
внизу под таблицами. Шрифт системный, поэтому на рабочем компьютере сайт выглядит не так,
как на домашнем.

## Решение

Сайт становится рабочим местом. Слева на каждой странице постоянная панель со всеми
инструментами вкладки и переключателем «Экспорт / Импорт». Справа — сама работа:
на главной «маршрут» (обычный порядок работы) и карточки инструментов, на странице
инструмента — три шага наверху, файлы с числом строк и закреплённая внизу полоса
с одной главной кнопкой. После обработки сразу видны главные цифры и кнопка «Скачать».
Цвета морской карты, шрифты Onest и JetBrains Mono встроены в сайт и не зависят ни
от компьютера, ни от интернета. Сами инструменты считают ровно так же, как сейчас.

Эталон внешнего вида — макет Б в `reference/design-options.html` (он же опубликован
по ссылке из брифа). Макет — уменьшенная картинка: размеры шрифтов и отступов на
настоящем сайте крупнее (см. «Решения по реализации» §6).

## Решения по реализации

### 1. Каркас страницы

Каждая страница — две колонки: панель (`<aside>` шириной ~272 px, во всю высоту окна,
`position: sticky`) и рабочая область (`<main>`, max-width ~920 px, отступы 32–40 px).
Панель рисует общий скрипт по `window.TOOLS`; в HTML страницы — только пустой
контейнер для неё. Почему так: одна запись в `tools.js` должна менять панель на всех
десяти страницах сразу (R14, R11, G01), а десять копий меню разойдутся с первой правкой.

Панель показывает все инструменты открытой вкладки; инструменты второй вкладки —
одним нажатием переключателя над списком. Так на макете Б, и так бриф описывает панель:
«со всеми инструментами» и «с переключателем «Экспорт / Импорт»» одновременно — без
переключателя это был бы один общий список, и переключатель был бы не нужен.

Детали, которых нет в тексте брифа, но есть на макете Б и потому входят в «Вариант Б»:
карточки инструментов под маршрутом, крошки над заголовком («ЭКСПОРТ / ОБЪЕДИНИТЬ
МАНИФЕСТЫ»), метки формата у пунктов панели, короткие имена в панели и маршруте,
«✕» у файлов, переключатель-тумблер у параметра склейки.

Узкий экран (< 900 px): панель превращается в верхнюю полосу (название сайта,
переключатель вкладок, кнопка «Инструменты»), список инструментов раскрывается
под ней. Строка про файлы — под полосой.

### 2. `tools.js` — единственный источник списка

Порядок записей = порядок в панели, маршруте и карточках (внутри каждой вкладки).
Новый порядок: Объединить манифесты (export) · Сверить опасные грузы (import) ·
Дашборд по портам назначения (import) · Дашборд по портам отправления (import) ·
Сверить с поручениями на погрузку (export) · Итоговый отчёт (export) · Сводный реестр
(export) · Разделить коносаменты (import) · Разделить коносаменты (export) — так, чтобы
отфильтрованный по вкладке список давал ровно порядок из истории 6. Две новых
необязательных поля у записи:

- `navTitle` — короткое имя для панели и маршрута («Сверить с поручениями», «Итоговый отчёт», «Реестр поручений и коносаментов»); нет — берётся `title`;
- `output` — метка формата результата: `xlsx`, `pdf`, `zip`.

### 3. Число строк у файла манифеста

`rowHasData` переезжает из `merge/core.js` в `lib/manifest-format.js` (экспортируется,
`merge/core.js` импортирует его оттуда — правило одно, в одном месте). Рядом —
`countDataRows(workbook) -> number | null`: число строк от `DATA_START_ROW` до конца
листа `SHEET_NAME`, у которых `rowHasData`; `null`, если листа нет. Это ровно то число,
которое склейка показывает в «Строк» — строка-довесок с `СУММ()` тоже считается, как и
там (иначе список и отчёт на одной странице разойдутся).

Страницы читают `.xlsx`-манифест при добавлении (ExcelJS уже подключён), вызывают
`countDataRows` и выводят число. При запуске инструмент читает файлы заново, как
сейчас — логика запуска не трогается. Для не-манифестов (DG-манифест, поручения,
`.zip`, `.pdf`) — размер файла.

### 4. Шаги по страницам

| Страница | 1 | 2 | 3 |
|---|---|---|---|
| Объединить манифесты | Файлы | Параметры | Результат |
| Итоговый отчёт | Файлы | Параметры | Результат |
| Сверить опасные грузы | Сводный файл | DG-манифест | Результат |
| Сверить с поручениями | Сводный файл | Поручения | Результат |
| Дашборды, Реестр, Разделить коносаменты | Файлы | Запуск | Результат |

Бриф задаёт формулу «Файлы → параметры → результат» и сам же приводит пример сверок
(«1. Сводный файл», «2. DG-манифест»). Поэтому: где у инструмента параметры есть —
подпись буквально «Параметры» (склейка: сквозная нумерация; Итоговый отчёт: позывной,
дата прибытия, терминал — у этой страницы шаг 2 тоже «Параметры», заголовок блока
внутри шага — «Данные судна»); у сверок — подписи из примера брифа. У четырёх
инструментов без параметров (два дашборда, реестр, «Разделить коносаменты») второй
шаг — «Запуск»: файлы на месте, осталось нажать кнопку. Шаг «Параметры» с пустым
содержимым соврал бы, что там что-то есть. Это осознанное отступление от буквы брифа —
будет названо в отчёте.

У двух сверок шаг 2 — тоже загрузка файла: текущий шаг 1, пока нет сводного, 2 — пока
нет второго, 3 — после результата.

### 5. Главные цифры результата (только из того, что уже возвращают `core.js`)

| Инструмент | Плитки | Кнопки рядом |
|---|---|---|
| Объединить манифесты | Строк · Уникальных контейнеров · Вес груза (если найден) | Скачать |
| Итоговый отчёт | Контейнеров (сумма по типам) · Общий вес · Коносаментов | Скачать PDF (главная) · Скачать Excel |
| Дашборды | Портов · Контейнеров · Общий вес — по итогу всех файлов | Скачать в Excel |
| Реестр | Пар · Уникальных поручений · Уникальных коносаментов | Скачать в Excel |
| Разделить коносаменты | Коносаментов · Предупреждений (если есть) | Скачать архив (.zip) |
| Сверить опасные грузы | Строк с расхождениями · Контейнеров не найдено — те поля, что есть в `summary` | Скачать |
| Сверить с поручениями | Контейнеров с расхождениями · По категориям — первые 2–3 из `summary` | Скачать |

Точные поля для двух сверок:

- «Сверить опасные грузы» — `summary.mismatchCount` («Строк с расхождениями»), `summary.notFoundInSummaryCount` («Нет в сводном файле»). Две плитки.
- «Сверить с поручениями» — `summary.totalRows` («Строк проверено»), `summary.mismatchRows` («С расхождениями»), `summary.missingFromSummary` («Нет в своде», только если не 0). Категории (`orderFormat`, `orderWrong`, `notFound`, `futnost`, `cargoWeight`, …) остаются списком под плитками, как сейчас.

Если какого-то поля в `summary` нет — плитки для него нет; новые подсчёты не заводятся.

без изменений по содержанию.


Шрифты: Onest (400/500/600/700 из одного переменного файла) — весь интерфейс;
JetBrains Mono — «номера и коды»: номера контейнеров, коносаментов и поручений в
таблицах результата, коды (ISO-тип, UN, порт), числа и веса в таблицах и плитках, числа
строк у файлов, номера шагов, метки форматов, крошки. Базовый размер текста 17 px, заголовок страницы 30 px, подзаголовок 18 px.
Скругления 10 px у карточек/списков, 8 px у кнопок. Тени не используются, только
рамки `--line`. Декор — тонкие линии изобат внизу панели, как на макете (SVG в CSS).
Тёмной темы нет — сайт одноцветный светлый, как и сейчас.

### 7. Шрифты — источник

Переменные woff2 из пакетов Fontsource (`@fontsource-variable/onest`,
`@fontsource-variable/jetbrains-mono`, лицензия OFL-1.1), подмножества cyrillic и latin —
четыре файла, ~100 КБ. Сами файлы шрифта лежат рядом с сайтом — `assets/fonts/`, вместе
с текстом лицензии OFL (как и обещано: «файлы шрифта лягут рядом с сайтом, а не на
Google»). Браузеру они отдаются через `assets/fonts.css`, где те же байты встроены как
base64 с `unicode-range`: при открытии страницы двойным кликом браузеры не дают
`file://`-странице загрузить шрифт отдельным файлом, а обещание было «будет работать
и при открытии файла двойным кликом». `fonts.css` делается из файлов в `assets/fonts/`
один раз, при разработке; сборки у сайта по-прежнему нет. Скачивание — только с разрешения
пользователя (вопрос перед разработкой).

### 8. Кэш

Каждый изменённый файл получает новый `?v=<YYYYMMDDHHMM>` во всех ссылках на него,
по цепочке из CLAUDE.md: `lib/manifest-format.js` → `core.js`, что его импортируют →
их `app.js` → `<script src="app.js?v=">` в `index.html` страницы. Новые файлы
(`assets/shell.js`, `assets/fonts.css`) подключаются сразу с `?v=`.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `tools.js` | список инструментов, их порядок, вкладки, короткие имена, форматы | `window.TOOLS: Array<{title, navTitle?, description, href, category: 'export'\|'import', output?: 'xlsx'\|'pdf'\|'zip'}>` | — |
| `assets/shell.js` (обычный скрипт) | панель, переключатель вкладок, мобильное меню, крошки, шаги, полоса действия | `window.Shell.plural(n, one, few, many) -> string` · `window.Shell.setStep(n: 1\|2\|3)` · `window.Shell.setAction({info: string, hint: string\|null})` · `window.Shell.setResultShown(shown: boolean)` · `window.Shell.formatSize(bytes) -> string` | вычисление корня сайта от своего `src`, определение текущего инструмента по адресу, хранение вкладки, разметку панели |
| `lib/manifest-format.js` | формат манифеста | + `rowHasData(sheet, rowNumber) -> boolean` · + `countDataRows(workbook) -> number \| null` | — |
| `assets/style.css` | весь внешний вид | классы: `.app`, `.app__side`, `.app__main`, `.steps`, `.dropzone` (+`__hint`), `.file-list` (+ `__meta`, `__remove`), `.action-bar` (+`__info`, `__hint`), `.btn`, `.btn--secondary`, `.result__head`, `.stat`, `.data-table`, `.error-message`, `.warning-message` | — |
| `assets/fonts.css` | шрифты | `font-family: "Onest"`, `"JetBrains Mono"` | base64 |
| `<tool>/app.js` | состояние своей страницы | — (вызывает `Shell.*`, `countDataRows`) | — |

Контракт разметки страницы инструмента (то, что читает `shell.js`):
`<body class="app">`, пустой `<aside class="app__side" id="app-side"></aside>` первым
ребёнком `body`, `<main class="app__main">`, внутри — `<ol class="steps" id="steps">`
с тремя `<li>` (подписи из §4), `<div class="action-bar" id="action-bar">` c
`<p class="action-bar__info" id="action-info">`, `<span class="action-bar__hint"
id="action-hint">` и главной кнопкой инструмента (её `id` прежний). Главная страница —
тот же каркас без шагов и полосы. Скрипты: `tools.js`, затем `assets/shell.js`, затем
библиотеки и `app.js` страницы.

`Shell.setResultShown(true)` делает главной **первую** кнопку внутри `.result__head`
(остальные там — `.btn--secondary`) и переводит кнопку запуска в полосе в
`.btn--secondary`; `false` — обратно. Пурпурная кнопка на экране всегда одна.
Какую кнопку считать кнопкой запуска — главная кнопка в `#action-bar`.

Швы для тестов: `countDataRows` / `rowHasData` в `lib/manifest-format.test.js`
(Node, как все остальные тесты). Поведение страниц — ручная проверка в браузере
(дев-сервер `manifest-tools` из `.claude/launch.json`): в репозитории нет DOM-тестов, и
заводить их ради редизайна — новый шов, который потом нельзя сдвинуть.

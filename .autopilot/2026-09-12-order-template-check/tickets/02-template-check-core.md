# 02 — Проверка шаблона: форма, сверка с поручением и три результата

**Требования:** R04, R05, R06, R07, R08, R09, R11, R12, R13, R14, R15i, R16i, G01, G02, A01, A02, A03, A04, A05, A06, A07
**Blocked by:** 01
**Зона:** `template-check/` — модули `core.js`, `template-form.js` и их тесты (не `index.html` и не `app.js` — это таск 03)
**Волна:** 2
**Status:** ready

## Что должно заработать

Чистый модуль, который по книге шаблона эл. поручения и одному или нескольким поручениям:

1. находит все ошибки формы (имя листа, лишние листы, шапка рейса, строка и порядок заголовков, лишние/недостающие колонки, пустые строки и строки «итого», объединения, вид чисел и дат);
2. сверяет каждый контейнер с поручением;
3. отдаёт три результата: книгу заказчика с жёлтыми ошибочными ячейками и примечаниями, исправленный шаблон по эталонной форме (если есть что исправить без заказчика) и текст отчёта для `.txt`.

Плюс распознавание файла: шаблон, поручение или ни то ни другое.

Страница (таск 03) только вызывает `detectFileKind` и `checkTemplate` и показывает результат — вся логика здесь.

## Из брифа, дословно

> «Этот инструмент должен сверять данные которые прописали в шаблоне с данными в поручении. также обязательно должна быть сверка соответствия шаблону по форме и названия листа иначе не получиться его загрузить в систему.»
> «на выходе должен быть шаблон с отмеченными желтым цветом неверными ячейками, а также текстовый документ с описанием ошибок. Если есть возможность внести изменения без уточнения у заказчика должна появляться кнопка по выгрузке исправленного шаблона»
> «Они оба заполнены корректно.»
> Дополнения: «Количество мест сверять но никогда не исправлять.» · «ВГМ больше либо равно вес груза+вес контейнера» · «делай первое» (кнопка — когда исправимо хоть что-то; «никогда — места и то, чего в поручении нет: коносамент, даты, английское наименование, упаковка, объём») · «txt, с датами согласен.»

## Как сделать

- `template-check/template-form.js` — только описание формы, как `lib/manifest-format.js`: константы §3 и `normalizeHeader`. Если внутреннему устройству удобно — разбор чисел и дат тоже можно держать там.
- `template-check/core.js` читает шаблон один раз в модель: шапка, карта колонок, строки с адресами исходных ячеек и «сырыми» значениями. Все правила работают по модели. Потом из модели и находок строятся три результата. Внутреннее устройство — на усмотрение исполнителя; наружу — только две функции из `interfaces.md`.
- Разбор поручения — только через `parseLoadingOrder` из `lib/loading-order.js` (таск 01). Своей копии разбора не заводить.
- Проверено на ExcelJS 4.4.0 оркестратором:
  - `cell.note = 'текст'` пишет примечание Excel;
  - `worksheet.properties.tabColor = {argb: 'FFFFFF00'}` красит ярлык;
  - `worksheet.name = '…'` переименовывает;
  - у ячейки внутри объединения `cell.value` отдаёт значение главной ячейки, а `.text` может бросить исключение (CLAUDE.md) — читать через try/catch;
  - список объединений — `worksheet.model.merges`;
  - дата Excel читается как `Date` в полночь UTC.
- Заливка — через клон стиля (`cloneStyle`), иначе покрасятся соседние ячейки с тем же стилем (в образце 1 так у всех строк данных).
- Перед возвратом шаблона с пометками — `dropUnwritableConditionalFormatting` из `lib/xlsx-safe-write.js` на каждом листе.
- Тесты — только синтетические книги, собранные программно по устройству из `reference.md`. Удобно завести в тесте сборщики «эталонный шаблон» и «эталонное поручение» с правками поверх. Настоящие файлы заказчика в репозиторий не кладутся (пути и правило — `interfaces.md`).

## Критерии приёмки

- [ ] `template-form.js`: константы §3 ровно — имя листа, шесть подписей шапки с их строками, `G3` и её текст, строки 8 и 9, 26 колонок (буква, заголовок, вид, обязательность, ширина); `normalizeHeader` как в §3.
- [ ] `detectFileKind`:
  - поручение → `order` с номером и числом контейнеров;
  - эталонный шаблон → `template` с числом строк с контейнером;
  - шаблон с листом «Лист1», но с верными заголовками → `template`;
  - посторонняя книга → `unknown`;
  - поручение проверяется первым.
- [ ] **Форма** — по тесту на каждое правило §4.1–§4.5 через `checkTemplate`: уровень, `fix`, `cell` по таблице §5.5, `field`, понятный `message`. Правила:
  - имя листа; лишний лист;
  - подпись шапки не на месте, неточная, отсутствует — СУДНО/РЕЙС из поручения «исправлю сам», даты и терминалы «уточнить у заказчика»;
  - строка заголовков не 8-я; неточный заголовок; колонка не на месте; нет колонки — обязательной и необязательной; заголовок дважды; лишняя колонка с данными;
  - пустая строка внутри таблицы; строка «итого»; строка без контейнера, но с текстом; ни одной строки с контейнером;
  - объединённые ячейки;
  - L/M/O текстом — «исправлю сам»; K/N текстом — «уточнить у заказчика»;
  - даты датой Excel или в другом виде — «уточнить у заказчика»;
  - NBSP по краям номера коносамента — **не находка**.
- [ ] **Сверка** — по тесту на каждую строку таблиц §5.1 и §5.2, в том числе:
  - G01: один товар, мест не столько → ошибка «уточнить у заказчика»; несколько товаров → предупреждение; ячейка K в исправленном шаблоне не меняется;
  - G02: ВГМ, равный грузу + таре, — не ошибка; меньше — «исправлю сам» на «Брутто груза с весом контейнера»; то меньше суммы — «уточнить у заказчика»;
  - ISO §5.4: 40HC ≡ 45G1, 40DV ≢ 45G1, 2200 ≡ 22G1, 4532 ≡ 40RH, неразобранные коды — сравнение строк;
  - несколько поручений: контейнер из другого поручения → B «исправлю сам»; контейнер в двух поручениях и B ни одному не равен → «уточнить у заказчика»;
  - B с незагруженным поручением → `topWarnings`, строки не сверены;
  - «похоже, загружено не то поручение»; разные судно/рейс у поручений;
  - предупреждения A01 (даты: 30/90 дней, дата коносамента раньше прихода), A03, A04, A05, A06, A07;
  - W при опасном грузе в поручении; Z при SOC/LOC; контейнер поручения не в шаблоне; повтор контейнера.
- [ ] **Шаблон с пометками**:
  - жёлтая заливка только у ячеек ошибок; соседние ячейки с тем же исходным стилем — не жёлтые;
  - примечания — у ошибок и предупреждений, несколько находок на ячейке — одно примечание;
  - ярлыки листов при листовых ошибках — жёлтые;

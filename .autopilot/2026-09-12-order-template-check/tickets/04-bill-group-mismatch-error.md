# 04 — Расхождение общих полей коносамента: предупреждение → ошибка

**Требования:** G03 (уточняет A07 из таска 02)
**Blocked by:** 02
**Зона:** `template-check/core.js`, `template-check/core.test.js`
**Волна:** 4
**Status:** ready

## Что должно заработать

Внутри одного коносамента дата коносамента (C), терминал выгрузки (F), SHIPPER/SHIPPER_ADDRESS/CONSIGNEE/CONSIGNEE_ADDRESS/NOTIFY/NOTIFY_ADDRESS (P, Q, R, S, T, U) сейчас сверяются по строкам того же коносамента (правило A07, таск 02), но расхождение — только предупреждение, ячейка не красится. Пользователь явно попросил защиту от протягивания данных в Excel: расхождение должно стать **ошибкой** — жёлтая заливка, «уточнить у заказчика» (не исправляется автоматически: нельзя знать, какая из разошедшихся строк верна, а какая испорчена). При этом находка должна появляться **на каждой** расходящейся строке, а не только на первой встреченной — сейчас `reported`-множество в `checkBillGroups` гасит повторные находки того же (коносамент, поле) на других строках.

## Из брифа, дословно

> «необходимо добавить проверку, чтобы все значения во всех строчках были одинаковыми (защита от искажения при протягивании данных в excel)»

Уточняющий вопрос координатора и ответ пользователя: «Сделать ошибкой» (из двух вариантов — оставить предупреждением или сделать ошибкой).

## Разделы спецификации

Решения §5.2 (строка «разные общие поля», таблица), §5.5 (таблица «ячейка находки», строка A07/G03). История 17c.

## Как сделать

Всё в `template-check/core.js`, функция `checkBillGroups` (сейчас у неё в файле комментарий `// A07: у строк одного коносамента общие поля должны совпадать.`):

- Находки этой функции сейчас идут через `ctx.warnings.push(finding({level:'warning', ...}))`. Нужно `level:'error', fix:'customer'` и класть их туда же, куда кладёт похожая по духу проверка `checkMissingContainers` (`ctx.data` или `ctx.missing` — посмотри, какой из двух массивов семантически ближе; главное, чтобы находка попала в `findings` и в `errors = findings.filter(f => f.level === 'error')`, откуда считаются `summary.errors`/`needsCustomer` и красится ячейка в `buildMarkedWorkbook`).
- Текст находки поправь под уровень «ошибка» (сейчас он написан для предупреждения — «проверьте»); формулировка на твой выбор, в духе остальных ошибок сайта («уточнить у заказчика»), без слова «предупреждение»/«проверьте».
- Убери гашение повторных находок того же (коносамент, поле) на разных строках — `reported`-множество (или что от него останется) не должно мешать пометить **каждую** расходящуюся строку; сравнение по-прежнему с первой строкой этого коносамента (`first`), она сама не помечается.
- Ничего не исправляй автоматически для этого правила (`fix:'auto'` здесь не ставить) — G03 явно об этом просит.
- Больше ничего в файле не трогай — остальные правила (§4, §5.1, другие пункты §5.2) не меняются.

## Критерии приёмки

- [ ] Синтетический шаблон: коносамент из 3+ строк, у одной строки SHIPPER отличается от первой строки того же коносамента → находка `level:'error', fix:'customer'`, ячейка этой строки в столбце P жёлтая, у первой строки (эталона) — не жёлтая (если по ней нет других находок).
- [ ] Тот же сценарий для каждого из остальных semи полей (C, F, Q, R, S, T, U) — хотя бы по одному тесту на представителя (не обязательно на все восемь порознь, если один тест параметризован по списку полей).
- [ ] Коносамент из 4 строк, у строк 2 и 4 CONSIGNEE отличается от первой строки (у строки 3 — совпадает) → **две** находки (по строке 2 и по строке 4), не одна.
- [ ] Коносамент, где все строки совпадают по всем восьми полям → находок по этому правилу нет.
- [ ] Два разных коносамента в одном файле, каждый со своими (одинаковыми внутри себя) значениями — находок нет, хотя между коносаментами значения различаются (сравнение строго внутри одного коносамента).
- [ ] `summary.errors`/`summary.needsCustomer` учитывают эти находки; `summary.warnings` их больше не считает.
- [ ] Отчёт (`buildReportText`) показывает такую находку в разделе «УТОЧНИТЬ У ЗАКАЗЧИКА», не в «ПРЕДУПРЕЖДЕНИЯ».
- [ ] На обеих настоящих парах пользователя (пути — `interfaces.md`) результат не меняется: в каждом файле один коносамент, и во всех его строках общие поля и так совпадают — новых находок не появляется. Проверить скриптом во временной папке, не в репозитории.
- [ ] Существующие тесты `template-check/core.test.js` на прежнее (warning-) поведение A07 — переписаны под новый уровень, не оставлены дублировать проверку старого поведения.
- [ ] `npm test` зелёный целиком.

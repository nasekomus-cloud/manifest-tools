# Спецификация: инструмент «Проверить шаблон эл. поручения»

## Задача

Заказчик (экспедитор) присылает письмом два файла: заполненный им «шаблон эл. поручения» (Excel, лист `EXPORT_MANIFEST`) и само поручение на погрузку. Шаблон потом загружается в систему. Сейчас его сверяют с поручением глазами, клетка за клеткой. Если в шаблоне не та форма — другое имя листа, сдвинутые или переименованные колонки, — система файл не примет. Если данные расходятся с поручением, в систему уйдёт неверный вес, пломба или тип контейнера. Нужен инструмент, который делает эту проверку сам: показывает, что не так, готовит текст для заказчика и сам исправляет то, для чего заказчик не нужен.

## Решение

Новый, самый первый инструмент во вкладке «Экспорт» — «Проверить шаблон эл. поручения». В него бросают файлы из письма: оба `.xlsx` или архив `.zip`, как его отдаёт почта. Инструмент сам различает, где шаблон, где поручение. Он проверяет **форму** (имя листа, шапку рейса, заголовки и порядок колонок, где начинаются данные, в каком виде записаны числа и даты) и **данные** (сверяет каждый контейнер шаблона с поручением).

На выходе:

1. **Шаблон с пометками** — исходный файл заказчика, неверные ячейки залиты жёлтым, в каждой — примечание Excel, что именно не так.
2. **Отчёт `.txt`** для Блокнота. Сначала — что уточнить у заказчика (готовый текст для письма), потом — что исправлено автоматически, потом — предупреждения «проверьте сами».
3. **Исправленный шаблон** — кнопка появляется, когда хотя бы одну ошибку можно исправить без заказчика. Файл собран строго по эталонной форме, в нём исправлено всё исправимое. Остальное оставлено как было, а рядом с кнопкой написано, сколько ошибок осталось уточнить у заказчика.

Эталон формы и соответствие полей поручению выведены из двух присланных пар файлов — разбор в `reference.md`.

## Решения по реализации

### §1. Стек и место на сайте

Как всё на сайте: статическая страница, `app.js` — ES-модуль, логика — в чистом модуле без DOM, который принимает готовые `ExcelJS.Workbook` снаружи и тестируется в Node (`node --test`, npm-пакет `exceljs`). В браузере — ExcelJS 4.4.0 и JSZip 3.10.1 с cdnjs, те же теги и версии, что на странице «Сверить с поручениями». Новых библиотек нет. Почему: так устроены все восемь инструментов, и это держит тесты в Node.

### §2. Разбор поручения — общий модуль

Формат поручения уже читает «Сверить с поручениями». Новый инструмент читает те же файлы, но ему нужно больше полей. Поэтому разбор поручения выносится в общий модуль (`lib/loading-order.js`), и «Сверить с поручениями» переводится на него без изменения поведения. Почему: исключение поддонов и точный поиск заголовков уже однажды ловили реальные ошибки (CLAUDE.md, «Подводные камни»), и это правило сайта — такая логика живёт в одном месте, как `lib/port-breakdown.js`.

Что модуль берёт из поручения (всё проверено на обеих парах, `reference.md`):

- **Шапка.** Подписи ищутся точным совпадением текста ячейки (`trim().toLowerCase()`) в строках выше заголовка таблицы; значение — в соседней ячейке справа: `номер поручения`, `дата`, `клиент`, `инн`, `отправитель`, `отправитель (англ)`, `грузополучатель`, `грузополучатель (англ)`, `извещение`, `судно`, `рейс`, `порт погрузки`, `порт выгрузки`. Без номера поручения файл поручением не считается.
- **Таблица.** Строка заголовков — та, где в колонке A стоит `номер контейнера` (в первых 20 строках). Колонки ищутся по точному тексту заголовка: `номер контейнера`, `владелец, soc / loc/-`, `код исо`, `номер пломбы`, `наименование груза, род упаковки`, `число мест`, `класс опасности`, `код опасности`, `нетто груза`, `брутто груза`, `вес контейнера`, `брутто груза с весом контейнера`. Обязательны `номер контейнера`, `брутто груза`, `вес контейнера`. Таблица кончается строкой `дополнительные сведения`.
- **Контейнер** — строка с номером открывает группу, строки ниже без номера — ещё товары того же контейнера. Строка, где наименование груза — ровно одно из «поддоны/поддон/палеты/палета/паллеты/паллета», это вес поддонов, а не товар. Её брутто идёт в `palletWeight`, места не считаются.
- Про каждый контейнер модуль отдаёт:
  - номер как в файле;
  - строку в поручении;
  - владельца (SOC/LOC);
  - ISO-код;
  - пломбу;
  - места — сумма «Число мест» по товарам (в файле это текст `40.0000`);
  - число товаров и их наименования;
  - вес груза — сумма «Брутто груза» по товарам без поддонов;
  - вес поддонов;
  - вес контейнера и «Брутто груза с весом контейнера» — из первой строки группы;
  - набор «класс|UN» по всем строкам группы.
- Модуль отдаёт контейнеры **списком в порядке файла**. Индекс по номеру каждый потребитель строит сам: «Сверить с поручениями» — по `trim()`, как сейчас (если номер повторился, выигрывает последний), новый инструмент — по нормализованному номеру.
- Тексты ошибок модуль отдаёт без префикса файла: `нет ни одного листа`, `не найден номер поручения`, `не найден заголовок «Номер контейнера»`, `не найдены обязательные колонки таблицы контейнеров`. Префикс `Файл «…»: ` добавляет «Сверить с поручениями», как сейчас, — её сообщения не меняются.

**Доказано кодом, таск 01 (D01).** Два решения этого раздела чуть меняют поведение «Сверить с поручениями» на нестандартных файлах: остановка таблицы на «дополнительные сведения» и поиск подписей во всех строках выше таблицы. Раньше текст в колонке A ниже «Дополнительные сведения» открывал ложный «контейнер», а повтор номера там подменял данные настоящего. Раньше номер поручения в строках 6–7 не находился. Теперь и то и другое читается верно. На настоящих поручениях пользователя разницы нет. Принято как исправление; «без изменения поведения» выше относится к правильным файлам.

Туда же, в общий модуль (`lib/xlsx-safe-write.js`), переезжает `dropUnwritableConditionalFormatting` из «Сверить с поручениями». Новый инструмент тоже пересохраняет файл заказчика (шаблон с пометками), и баг ExcelJS 4.4.0 с условным форматированием неподдерживаемого типа (CLAUDE.md) касается его так же.

### §3. Эталонная форма шаблона

Эталонная форма описана в одном месте — отдельном модуле формы шаблона (`template-check/template-form.js`), как `lib/manifest-format.js` для манифеста: если система поменяет шаблон, правится только он. Всё взято из двух образцов (`reference.md`).

- Лист: `EXPORT_MANIFEST`, единственный в книге.
- Шапка рейса: подписи в колонке D, значения в колонке E, строки 1–6: `СУДНО`, `РЕЙС`, `ДАТА ПРИХОДА`, `ДАТА ВЫХОДА`, `ТЕРМИНАЛ ПОГРУЗКИ`, `ТЕРМИНАЛ ВЫГРУЗКИ`.
- `G3`: `Таблицу заполнять строго в соответствии с п/поручением и ДТ!` — это оформление, не данные: её отсутствие не ошибка, в исправленном шаблоне она есть всегда.
- Строка 7 пустая. Заголовки — строка 8. Данные — с 9-й, одна строка на контейнер.
- Колонки (номер, заголовок ровно так, вид значения, обязательность):

| № | Заголовок | Вид | Обяз. | № | Заголовок | Вид | Обяз. |
|---|---|---|---|---|---|---|---|
| A | НОМЕР КОНОСАМЕНТА | текст | да | N | ОБЪЕМ | число | да |

- **Вид значения** в эталонной форме:
  - дата — текст `ДД.ММ.ГГГГ`;
  - число — числовая ячейка;
  - пломба — число, если это одни цифры без ведущего нуля (как в образцах), иначе текст: `0012345` числом потерял бы нули;
  - текст — текст.

  - значения шапки — Arial Cyr 10 полужирный, по левому краю;

  - данные — Arial 8, по центру, тонкая рамка, перенос в G, H, P–U;
  - высота строк 1–6 — 23,25, строк данных — 30;
  - ширины колонок как в образце 1: A, B 18,57; C 14,71; D 22,43; E 12; F 16,71; G 26,14; H 22,43; I 15,14; J 13,29; K 14,57; L, M, N 12; O 12,43; P 20; Q 27,71; R–T 13,43; U 16,57; V 15; W 17,14; X 12,71; Y 16; Z 12,71;
  - формат ячеек текстовых колонок и дат — `@`.

### §4. Проверка формы

Каждая находка — ошибка (исправлю сам / уточнить у заказчика) или предупреждение. «Исправлю сам» здесь значит: эталонная форма соберёт это правильно без новых сведений от заказчика.

**Что исправленный шаблон не меняет никогда.** Пользователь согласился с перечнем (брифинг, «делай первое»): места и всё, чего в поручении нет — коносамент, даты, английское наименование, упаковка, объём. Поэтому ячейки **A, C, E3, E4, G, J, K, N** переносятся в исправленный шаблон ровно такими, какими их записал заказчик: то же значение и тот же вид (текст, число, дата Excel). Любая находка по ним — «уточнить у заказчика», даже когда дело только в виде записи. Тогда текст находки говорит «исправьте вручную или уточните у заказчика».

**Что исправляется из поручения** — поля, которые по эталону обязаны совпадать с поручением: **B, D, E, I, L, M, O, Z, E1, E2** (§5).

**Остальное переносится как есть.** Каждое значение, которое не исправляется, попадает в исправленный шаблон ровно как у заказчика: пробелы по краям (NBSP в номере коносамента образца 1) не убираются, вид ячейки не меняется. Два исключения, оба не меняют видимого значения:
- формула заменяется своим значением — в пересобранной форме её ссылки указывали бы не туда;
- ячейки объединения получают значение главной ячейки.

**4.1. Лист.**
- Лист шаблона: лист `EXPORT_MANIFEST`, если на нём есть строка заголовков; иначе первый лист, на котором она есть (строка заголовков — §4.3).
- Имя не ровно `EXPORT_MANIFEST` (другое слово, другой регистр, пробел в конце) → ошибка, исправлю сам.
- Любой другой лист в книге, в том числе скрытый → ошибка «лишний лист», исправлю сам.
- В шаблоне с пометками ярлыки таких листов жёлтые.

**4.2. Шапка рейса.** Каждая из шести подписей ищется в строках выше строки заголовков, в любой колонке, по нормализации §3. Значение — соседняя ячейка справа.
- Подпись нашлась не в D на своей строке, или записана неточно → ошибка, исправлю сам; жёлтой становится найденная подпись.
- Подписи нет → строки шапки нет.
- Значение пустое или строки нет:
  - `СУДНО`, `РЕЙС` → исправлю сам, из поручения;
  - даты и терминалы → уточнить у заказчика.
- Проверка значений шапки — §5.1.

**4.3. Заголовки колонок.**
- Строка заголовков — первая из строк 1–30, где нашлись по нормализации хотя бы 5 из 26 заголовков.
- Нет такой строки → файл не распознаётся как шаблон (§6).
- Строка заголовков не 8-я → ошибка, исправлю сам.
- По каждому из 26 заголовков:
  - нашёлся на своём месте и точно → в порядке;
  - нашёлся, но текст не точный → ошибка, исправлю сам, ячейка жёлтая;
  - нашёлся не в своей колонке → ошибка «колонка не на своём месте», исправлю сам, ячейка жёлтая;
  - не нашёлся → ошибка «нет колонки», исправлю сам: колонка появится в исправленном шаблоне. Её значения по строкам — отдельные находки по правилам §5: у обязательной колонки пустые значения — ошибки, исправимые или нет по §5.
- Один заголовок в двух колонках → ошибка, уточнить у заказчика; берётся первая, вторая — как лишняя.
- Непустой заголовок, который не узнан ни как один из 26 → ошибка «лишняя колонка», исправлю сам: в исправленном шаблоне её нет. Если под ней есть данные, в тексте находки — «данные этой колонки в исправленный шаблон не попадут».

**4.4. Строки данных.** Строки ниже строки заголовков до последней непустой.
- Пустая строка, после которой ещё есть данные → ошибка «пустая строка внутри таблицы», исправлю сам: в исправленном шаблоне её нет. Жёлтой становится ячейка A этой строки.
- Строка без номера контейнера, где заполнены только K–O числами → строка «итого», исправлю сам: в исправленном шаблоне её нет.
- Строка без номера контейнера, где есть что-то ещё → ошибка, уточнить у заказчика; в исправленном шаблоне остаётся как была.
- Ни одной строки с контейнером → ошибка, уточнить у заказчика.
- Объединённые ячейки в таблице или в шапке → ошибка, исправлю сам. ExcelJS отдаёт значение главной ячейки всем ячейкам объединения. В исправленном шаблоне объединений нет, значение стоит в каждой ячейке.

**4.5. Вид значений.** Одна ячейка — не больше одной находки. Если значение неверно по §5, находка про значение, и в её тексте упоминается вид («…и записано текстом»). Отдельная находка про вид — только когда само значение верно.

| Колонки | Ожидаемый вид | Что считается ошибкой вида | Как поступить |
|---|---|---|---|
| L, M, O | число | текст, который читается как число: `28120`, `28 120`, `28120,5`, `6220.216` (пробелы и NBSP убираются, запятая = точка; с двумя разными разделителями — не число) | исправлю сам — числом |
| K, N | число | то же | уточнить у заказчика («записано текстом — исправьте вручную или уточните у заказчика»); ячейка не меняется |
| K, L, M, N, O | число | текст, который числом не читается, или пусто | правила §5 |
| C, E3, E4 | текст `ДД.ММ.ГГГГ` — настоящая дата календаря | дата Excel (`Date`, в том числе число с форматом даты), текст в другом виде (`Д.М.ГГГГ`, `ДД.ММ.ГГ`, `ГГГГ-ММ-ДД`) или текст, который датой не читается | уточнить у заказчика; ячейка не меняется. Для правил §5.1 и §5.3 дата всё равно читается, если это возможно: дата Excel — по UTC-полям, как их отдаёт ExcelJS; `ДД.ММ.ГГ` — как 20ГГ |
| I | число или текст | не ошибка: в образцах пломбы числом, в поручении — текстом; оба вида верны | — |
| остальные (текстовые) | текст | число в текстовой колонке **не проверяется**: система читает его как текст, а в образцах таких случаев нет | — |

- **Пробелы по краям** текста, включая NBSP (так записан номер коносамента в образце 1), — не ошибка и не находка. При сравнении значения обрезаются, в исправленном шаблоне остаются как были.
- **Формула** — не ошибка. Для проверки берётся её результат, в исправленный шаблон идёт значение.

### §5. Сверка данных с поручением

Строка шаблона находит своё поручение по контейнеру. Контейнеры сравниваются по нормализованному номеру: верхний регистр, без пробелов и дефисов.
- Контейнер есть в поручении из колонки B → сверка с ним.
- Контейнер есть только в другом загруженном поручении → сверка с тем поручением, а B — ошибка (ниже).
- Контейнер в нескольких загруженных поручениях → сверка с тем, чей номер в B; если B ни одному не равен — ошибка «уточнить у заказчика».
- Контейнера нет ни в одном поручении, а в B номер поручения, которого нет среди загруженных → строка не сверяется. Вверху результата предупреждение «Поручение X не загружено — N строк не сверены с поручением».
- Вес и число сравниваются с допуском 0,01.

**5.1. Шапка рейса**

| Ячейка | Правило | Уровень | Как поступить |
|---|---|---|---|
| E1 СУДНО | равно «Судно» поручения (без учёта регистра и лишних пробелов) | ошибка | исправлю сам — значение из поручения. Если у загруженных поручений разные суда — уточнить у заказчика |
| E2 РЕЙС | равно «Рейс» поручения, так же | ошибка | так же |
| E3, E4 | дата (§4.5) | ошибка | §4.5 |
| E3 ≤ E4 | дата прихода не позже даты выхода | ошибка | уточнить у заказчика |
| E5, E6 | не пустые | ошибка | уточнить у заказчика |
| — | у загруженных поручений разное судно или рейс | предупреждение | — |

**5.3. Даты — предупреждения** (A01, согласовано на брифинге):
- ДАТА ПРИХОДА, ДАТА ВЫХОДА, ДАТА КОНОСАМЕНТА раньше самой ранней даты загруженных поручений больше чем на 30 дней или позже самой поздней больше чем на 90 дней → предупреждение «проверьте год» с числом дней: «05.09.2027 — на 374 дня позже даты поручения 27.08.2026, проверьте год»;
- дата коносамента раньше даты прихода → предупреждение;
- голубая заливка (G04) и примечание, без исправления — правильную дату знает заказчик.

**5.4. ISO-код — один тип или нет.** Код раскладывается на (длина, высота, группа):
- **ISO 6346 из 4 знаков** (`[1-9L][0-9][A-Z][0-9]`):
  - длина: `2` → 20, `4` → 40, `L` → 45, `1` → 10, `3` → 30;
  - высота: `5`, `6` → HC; `0`–`4` → обычная; `8`, `9` → низкая;
  - группа — третий знак: G, R, U, P, T, B, V, H, S…;
- **старые цифровые коды** (`2200`, `4500`, `4532`): первые два знака — как выше, вторые два: 00–19 → G, 30–39 → R, 50–59 → U, 60–69 → P, 70–79 → T;
- **обиходные обозначения**:

  | Обозначения | Длина | Высота | Группа |
  |---|---|---|---|
  | 20DV/20DC/20GP/20ST/20SD | 20 | обычная | G |
  | 40DV/40DC/40GP/40ST/40SD | 40 | обычная | G |
  | 40HC/40HQ | 40 | HC | G |
  | 45HC/45HQ | 45 | HC | G |
  | 20RF/20RE | 20 | — | R |
  | 40RF/40RE | 40 | — | R |
  | 40RH/40HR/40RQ | 40 | HC | R |
  | 20OT, 40OT | 20 / 40 | — | U |
  | 20FR/20PL, 40FR/40PL | 20 / 40 | — | P |
  | 20TK/20TN | 20 | — | T |

  Прочерк в «Высота» — высота не известна и совпадает с любой.

Коды одного типа — у них равны длина и группа, а высота равна там, где она известна у обоих. `40HC` и `45G1` — один тип (образец 1). `40DV` и `45G1` — разные: обычный и high cube. Если хоть один код не разобрался, сравниваются строки без учёта регистра.

**5.5. Уровни, заливка и ячейка находки.**
- **Ошибка** — ячейка жёлтая (стиль клонируется перед записью, как везде на сайте), в примечании текст находки и «Исправлю сам» или «Уточнить у заказчика».
- **Предупреждение** — примечание и голубая заливка (`ADD8E6`, G04) — отличима от жёлтой заливки ошибок.
- Ячейка, у которой есть и ошибка, и предупреждение (по разным правилам) — жёлтая: ошибка важнее.
- Несколько находок на одной ячейке — одно примечание, строками.
- Адрес ячейки находки — по **исходному** файлу, он же идёт в отчёт и в таблицу на странице.

| Находка | Ячейка (`cell`) |
|---|---|
| значение в строке контейнера или в шапке | сама ячейка |
| имя листа, лишний лист | `null`; жёлтый ярлык у листа шаблона / у лишнего листа |
| строки шапки нет | `null` |
| подпись шапки не на месте или записана неточно | найденная подпись |
| строка заголовков не 8-я | первая (самая левая) узнанная ячейка заголовка |
| заголовок записан неточно / не на своём месте / лишняя колонка | ячейка этого заголовка |
| один заголовок в двух колонках | обе ячейки заголовка, по находке на каждую |
| колонки нет | `null` |
| пустая строка внутри таблицы | ячейка A этой строки |
| строка «итого» | первая непустая ячейка строки |
| строка без номера контейнера, но с другими данными | ячейка D этой строки |
| объединённые ячейки | главная (левая верхняя) ячейка каждого объединения, в тексте — диапазон |
| дата прихода позже даты выхода | E3 и E4, по находке на каждую |
| контейнер не найден / повторяется | ячейка D (при повторе — у каждого повтора) |
| контейнер в нескольких поручениях, B ни одному не равен | ячейка B |
| разные общие поля у строк одного коносамента (A07, G03) | ячейка **расходящейся** строки в этой колонке (не первой строки коносамента — она эталон сравнения, сама не красится) |
| дата коносамента раньше даты прихода | ячейка C |
| контейнер поручения, которого нет в шаблоне | `null` |
| предупреждения «вверху» (§8) | не находки, отдельный список `topWarnings` |

### §6. Распознавание файлов

При добавлении каждый `.xlsx` читается один раз, и модуль проверки говорит, что это:
- **поручение** — разбор §2 удался; в подписи — номер и число контейнеров;
- **шаблон** — в книге есть лист `EXPORT_MANIFEST` (без учёта регистра и пробелов) или строка заголовков §4.3 на любом листе; в подписи — число строк с контейнером;
- **ни то ни другое**.

Поручение проверяется первым: это более узкий признак. Для проверки файлы читаются заново, из исходных байтов: шаблон с пометками — это сам загруженный файл, изменённый на месте, и старый объект переиспользовать нельзя.

### §7. Отчёт `.txt`

Текст собирает модуль проверки, переводы строк `\r\n`. BOM добавляет страница при скачивании. Имя файла отчёта — `<имя шаблона без .xlsx> (отчёт).txt`. Шаблон с пометками — `… (пометки).xlsx`, исправленный — `… (исправлен).xlsx`. Структура — как в примере (данные условные):

```
ПРОВЕРКА ШАБЛОНА ЭЛ. ПОРУЧЕНИЯ
Проверено: 12.09.2026 23:40
Шаблон: НОВЫЙ шаблон эл_поручения export.xlsx (лист «EXPORT_MANIFEST», 10 контейнеров)
Поручение: 7826145796-P26-00002.xlsx — № 7826145796-P26-00002 от 07.09.2026, 10 контейнеров
Судно / рейс: GUANG QI DE ER TA / 2601E

ИТОГ: ошибок — 3 (исправлено автоматически — 2, уточнить у заказчика — 1), предупреждений — 1.

УТОЧНИТЬ У ЗАКАЗЧИКА — 1
1. K10, КОЛИЧЕСТВО МЕСТ, контейнер CIMU0502746: в шаблоне 38, по поручению 40.

ИСПРАВЛЕНО АВТОМАТИЧЕСКИ — 2 (уже внесено в «НОВЫЙ шаблон эл_поручения export (исправлен).xlsx»)
1. Лист «Лист1» → переименован в «EXPORT_MANIFEST».
2. L13, ВЕС ГРУЗА, контейнер SNBU8153520: в шаблоне 28000, по поручению 28120 → 28120.

ПРЕДУПРЕЖДЕНИЯ — ПРОВЕРЬТЕ САМИ — 1
1. E3, ДАТА ПРИХОДА: 05.09.2027 — на 374 дня позже даты поручения 27.08.2026, проверьте год.
```

- Пустой раздел не выводится.
- Без ошибок и предупреждений итог — «Ошибок и предупреждений нет — шаблон соответствует форме и поручению.»
- Если строки не сверены (поручение не загружено), предупреждение об этом — первым в разделе предупреждений.
- Адреса ячеек — по **исходному** файлу заказчика, то есть по шаблону с пометками.
- Строка «уточнить у заказчика» пишется так, чтобы её можно было вставить в письмо без правки.

### §8. Страница

- Одна зона: принимает `.xlsx` и `.zip`, несколько файлов. Подсказка: «Шаблон и поручение из письма заказчика — отдельными файлами или архивом .zip, как их отдаёт почта».
- В списке файлов у каждой строки — имя, подпись роли (§6, «распознаю…» пока читается) и «✕».
- Шаги: «Файлы от заказчика» → «Проверка» → «Результат». Кнопка запуска — «Проверить», на время работы — «Проверяю…».
- Полоса действия: `Шаблон: <имя> · Поручения: N`, подсказки — история 4.
- Любое изменение набора файлов прячет результат (`setChanged()` → `hideSummary()`).
- **Результат**:
  - плитки и таблица находок — история 24;
  - предупреждения «вверху» (не загружено поручение, похоже не то поручение, разные рейсы, нечитаемые файлы) — в `.warning-message`;
  - кнопки в `.result__actions` в таком порядке: «Скачать исправленный шаблон» (есть исправимые), «Скачать шаблон с пометками» (есть ошибки или предупреждения), «Скачать отчёт (.txt)» (всегда); скрытые — атрибутом `hidden`;
  - подпись про исправленный шаблон — история 22.
- **Каркас «Лоции»**: `Shell.setResultShown(true)` делает главной первую **видимую** кнопку в `.result__head`. Сейчас он берёт первую по порядку, даже скрытую. Правка — в общем каркасе, для остальных страниц ничего не меняется: у них скрытых кнопок в `.result__head` нет.
- Скачивание — как на остальных страницах: `Blob` → временная ссылка.

### §9. Версии, тесты, документация

- **Версии `?v=`** по правилу CLAUDE.md:
  - новые `app.js`, `core.js`, модули — со своими `?v=`;
  - `tools.js` и `assets/shell.js` меняются, их `?v=` обновляется на всех десяти страницах;
  - вынос разбора поручения тянет каскад `order-check`: `core.js` → `app.js` → `index.html`.
- **Тесты**:
  - файлы-образцы заказчика в репозиторий не кладутся;
  - тесты строят книги шаблона и поручения программно, по устройству из `reference.md`;
  - на каждое правило §4–§5 — хотя бы один тест через публичный шов;
  - отдельно — свойство истории 23 (исправленный шаблон проходит повторную проверку);
  - приёмка на настоящих парах — скриптом вне репозитория по путям во временной папке (история 28).
- **Документация**: CLAUDE.md дополняется в конце прогона.

- `detectFileKind` + `checkTemplate` — всё остальное. Правила, заливка, примечания, исправленный шаблон и отчёт проверяются через результат `checkTemplate`. Исправленный шаблон проверяется повторным `checkTemplate` на нём же.

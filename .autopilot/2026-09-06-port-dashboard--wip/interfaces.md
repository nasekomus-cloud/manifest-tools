# Что уже построено

Читается до начала работы. Не изобретай заново то, что здесь есть.

## Границы, решённые в спецификации

- `dashboard/core.js` — владеет подсчётом разбивки по портам/типам/весу.
  Выставляет: `buildPortDashboard(workbooks) -> {ok:true, perFile, combined} | {ok:false, error}`
  (`workbooks: Array<{fileName, workbook: ExcelJS.Workbook}>`).
  Прячет: поиск колонок по ключевым словам, нормализацию порта/типа, `Map`-группировку, сортировку.
- `dashboard/app.js` — DOM: загрузка файлов, рендер таблиц на странице, сборка и скачивание Excel-отчёта.
  Публичного контракта не выставляет (как `merge/app.js`/`dg-check/app.js`).
- Шов для тестов — один: `buildPortDashboard`. Тестируется без DOM и без файловой системы,
  как `merge/core.test.js`/`dg-check/core.test.js`.

## Общие правила проекта

- Стек: ES-модули без сборки, ExcelJS 4.4.0 через CDN-тег (как в `merge/index.html`/`dg-check/index.html`),
  в тестах — npm-пакет `exceljs` из `devDependencies`.
- Формат манифеста — `lib/manifest-format.js`: лист `"Manifest"`, шапка C:Y, заголовки в строке 5,
  данные с 6-й. Не дублировать эти числа — импортировать константы.
- Поиск нужных колонок — по ключевым словам в заголовке (`findColumnByKeyword`-приём из
  `merge/core.js`/`dg-check/core.js`), не по букве столбца. Ключевые слова для этого инструмента:
  «назначения» (порт), «футность» (тип контейнера), «груза» (вес груза), «тары» (вес тары),
  «общий» (общий вес). **Не использовать слово «вес» целиком** — в реальном файле-примере заголовки
  «Веc груза»/«Веc тары»/«Общий Веc» написаны с латинской `c` вместо кириллической (проверено
  побайтово), и слово «вес» в них не встречается ни разу.
- Тесты: `npm test` (`node --test`), команда для одного файла — `node --test dashboard/core.test.js`.
- Запуск локально: `python3 -m http.server` из корня, либо `dashboard/index.html` открывается
  напрямую (страница — `<script type="module">`, значит нужен http(s), не `file://`).
- Кэш GitHub Pages — 10 минут: все свои `<script src="...">`/`import ... from '...'` несут
  `?v=<YYYYMMDDHHMM>`; при правке файла — обновить число.
- Не трогать: `lib/manifest-format.js` (кроме импорта констант), `merge/`, `dg-check/` —
  зона этого захода — только `dashboard/`, `tools.js` (добавить карточку) и `.gitignore`/README не трогать.
- Если не хватает зависимости — не добавлять самостоятельно, вернуть `BLOCKED` с названием.

## Тир

Т0 — единственная поверхность (`dashboard/`), без внешних сервисов, без деления на таски.
Строится в один проход текущим контекстом, без relay-цепочки.

## Из прохода T0 — построено

- `dashboard/core.js` — `buildPortDashboard(workbooks) -> {ok:true, perFile, combined} | {ok:false, error}`,
  как и планировалось. Одно уточнение против спецификации: нормализация порта убирает
  пробел именно перед «(» (`.replace(/\s+\(/g, '(')`), а не произвольные повторные
  пробелы — «St.Petersburg, Timber Port (RUPLP)» и «…Port(RUPLP)» отличаются наличием
  ровно одного пробела, а не его количеством, и общее схлопывание `\s+` их не уравнивает.
  Спецификация обновлена тем же текстом.
- 11 тестов в `dashboard/core.test.js`, включая тест на реальную опечатку из
  файла-примера («Веc груза» с латинской `c`) и на схлопывание двух вариантов
  одного порта. Проверено также на самом файле-примере (`manifest_combined.xlsx`,
  915 строк, оба порта, все 6 типов контейнеров) — через браузерную страницу и
  через отдельный скрипт для проверки экспорта в Excel (round-trip чтения/записи).
- `dashboard/app.js` — рендер таблиц на странице (порт → типы → подытог по порту
  с CSS-полосой относительного веса → общий итог) и сборка/скачивание Excel
  (`sanitizeSheetName` — обрезка расширения, запрещённые символы на «_», лимит
  31 символ, суффиксы «(2)», «(3)» при совпадении имён листов).
- Карточка добавлена в `tools.js`, версия у `tools.js` в корневом `index.html`
  обновлена (`?v=202609061822`).

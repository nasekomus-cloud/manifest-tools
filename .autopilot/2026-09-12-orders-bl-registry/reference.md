# Эталон — вид готового результата

Приложены пользователем вместе с брифом:
- исходник: `/Users/nasekomus/Downloads/Gmail (5)/merged-manifest (2).xlsx` — сводный манифест (лист `Manifest`, тот же формат, что описан в `lib/manifest-format.js`; похож на результат инструмента «Склейка»), рейс «т/х GUANG Q» / «Рейс №2601E», 1779 строк данных.
- эталон результата: `/Users/nasekomus/Downloads/Gmail (5)/п-п_GQDE 2601E.xlsx` — один лист `Лист1`, 3 колонки: `№№` / `№ Поручения` / `№ Коносамента`, 131 строка данных + 2 итоговые строки внизу.

## Что подтверждено разбором обоих файлов

- В манифесте нужные данные — колонка O «№ коносамента» и колонка Y «№ поручения»; обе внутри диапазона `FIRST_COLUMN..LAST_COLUMN` (`C:Y`) из `lib/manifest-format.js`, «№ поручения» — ровно на границе (`LAST_COLUMN`). Искать обе по ключевому слову в строке `COLUMN_HEADER_ROW` (`findColumnByKeyword`, тот же приём, что уже в `order-check/core.js` — там колонка «поручения» ищется точно так же), а не по фиксированной букве.
- Строка без номера контейнера — как и везде на сайте — не данные (в этом файле такой строки-довеска с формулами не встретилось, но проверка нужна, как в `buildManifestTotals`).
- **Реестр — это уникальные пары (№ поручения, № коносамента), а не одна строка на контейнер.** Один и тот же коносамент/поручение в манифесте стоит на многих строках (пример: коносамент `OVPGPLPAQJ000027` — на 45 строках подряд, с одним и тем же поручением `7805128510-P26-00768`) — в эталоне это ровно одна строка реестра.
- **Итоговые строки внизу** — после пустой строки: `«N поручение»` и `«M коносаментов»`, где N/M — число **уникальных** значений в каждой из двух колонок реестра (в эталоне: 131 и 129 — не совпадают друг с другом, то есть считаются по своей колонке, а не по числу строк реестра).
- **Разбиение составных поручений — с досборкой префикса.** В двух местах манифеста одна ячейка «№ поручения» держит два номера через `"; "` (`7838133940-P26-00081; 00082` и `7838133940-P26-00087; 00088`) — в эталоне это две отдельные строки реестра с одним и тем же коносаментом. Второй номер в паре в манифесте сокращён (`00082`, без общего префикса) — **в эталоне он восстановлен целиком** (`7838133940-P26-00082`): недостающий префикс взят из первого номера пары, подстановкой по длине (первый номер длиной 20 символов, короткий фрагмент длиной 5 → берутся первые 20-5=15 символов первого номера как префикс + сам фрагмент). Проверено вычислительно на обоих реальных случаях — совпадает символ в символ.
- **Перенос строки внутри одиночного номера поручения удаляется целиком, не заменяется пробелом.** `7839474406-P26-00447\n/1` → `7839474406-P26-00447/1` (без пробела на месте `\n`). Тот же приём (удаление всех пробельных символов, не схлопывание) работает и для разбора составных ячеек: сначала делим по `;`, затем у каждой части убираем ВСЕ пробельные символы (включая внутренние), только потом — при необходимости — досборка префикса.
- **Дедупликация — по паре (поручение-после-разбора, коносамент)**, а не по исходному тексту ячейки: одна ячейка с двумя номерами через `"; "` даёт две отдельные пары в реестре, даже если коносамент у них общий.
- **Проверено полным пересчётом обоих файлов**: применение этого алгоритма к `merged-manifest (2).xlsx` даёт ровно 131 строку реестра, 131 уникальный номер поручения и 129 уникальных коносаментов — совпадает с итоговыми числами эталона «131 поручение» / «129 коносаментов» и с составом пар (кроме одной опечатки, см. ниже).
- **Оформление таблицы в эталоне** (найдено независимой проверкой покрытия спецификации, подтверждено побайтовым чтением стилей ячеек): рамка `medium` по внешнему периметру диапазона `A1:C132` (шапка + все строки данных), `thin` между остальными ячейками внутри него; две пустые строки без рамки (133, 134), затем итоговые строки 135–136 тоже без рамки и без номера в первой колонке.

## Что НЕ удалось объяснить разбором (решено в брифинге)

- **Порядок строк в эталоне не совпадает** ни с порядком первого появления пары в манифесте, ни с алфавитной/числовой сортировкой по коносаменту, ни с сортировкой по поручению. Похоже на порядок какого-то внешнего документа (например, исходного списка поручений от экспедитора), которого среди приложенных файлов нет — реконструировать его из одного манифеста нельзя.
  → **Вопрос задан пользователю, ответ: сортировать по номеру коносамента** (текстовая сортировка по возрастанию). Смысловое содержание (набор пар + итоговые числа) при этом полностью совпадает с эталоном; буквальный порядок строк — нет.
- Один расход в написании: коносамент `OVPGPLPEDK000114C` в манифесте — с латинской `C`, а в эталоне на той же позиции — `OVPGPLPEDK000114С` с кириллической `С`. Похоже на опечатку при ручной подготовке эталона, а не на правило инструмента — сверка ведётся по значению из манифеста как есть, без попытки угадать «настоящую» букву.

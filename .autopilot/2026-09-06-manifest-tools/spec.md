# Спецификация: Инструменты для судовых манифестов

## Задача

Жена периодически получает по электронной почте несколько файлов Excel с грузовым
манифестом одного рейса — по одному файлу на порт/терминал погрузки. Ей нужно:

1. Убедиться, что у всех файлов одинаковая структура, и склеить их в один общий файл,
   сохранив всё форматирование (шрифты, заливки, рамки, форматы чисел).
2. Сверить в этом общем файле данные об опасных грузах с отдельным официальным
   DG-манифестом (по номеру контейнера) и увидеть расхождения.

Сейчас это делается вручную или через Python-скрипт, который нужно запускать из
терминала — неудобно и требует технических навыков, которых у неё нет и не должно
быть нужно.

## Решение

Сайт с двумя инструментами-карточками на главной странице: «Объединить манифесты»
и «Сверить опасные грузы». Всё работает прямо в браузере — файлы никуда не
загружаются, обработка идёт на её компьютере, результат сразу скачивается файлом
`.xlsx`. Сайт открывается по обычной ссылке (GitHub Pages) с любого устройства,
ничего устанавливать не нужно. Позже на ту же главную страницу можно добавить
следующие инструменты, не трогая уже готовые.

## Решения по реализации

- **Стек: чистые HTML/CSS/JS, без сборки и без npm-зависимостей.** Публикуется на
  GitHub Pages как есть — ни шага сборки, ни сервера не нужно.
- **Единственная сторонняя библиотека — ExcelJS**, подключается `<script>`-тегом с
  CDN (`cdnjs.cloudflare.com`) в браузере. Это единственная популярная JS-библиотека,
  которая одновременно читает и пишет `.xlsx` **вместе со стилями** (шрифт, заливка,
  границы, формат чисел, ширины колонок) — то, что нужно для R06.
- **Вся обработка — на стороне браузера.** Файлы не отправляются никуда; сайт может
  быть публичным (открытым исходным кодом на GitHub), потому что через него не
  проходят чужие данные.
- **Формат манифеста (зашит как константа, проверяется явно):** лист с именем
  `Manifest`, шапка рейса — строки 3–5 (строка 5 — заголовки колонок), данные —
  с 6-й строки, диапазон колонок `C:Y`. Это подтверждённая структура всех шести
  файлов из примера. Слияние возможно только если у всех загруженных файлов один
  лист `Manifest` и одинаковый текст `C5:Y5`; иначе — ошибка с именем файла и
  первой несовпавшей ячейкой, без частичного результата.
- **Структура репозитория:**
  ```
  index.html                    — главная, список карточек-инструментов
  tools.js                      — общий конфиг карточек (для R04/A01)
  assets/style.css              — общий минимальный стиль
  merge/index.html, merge/app.js, merge/core.js    — инструмент 1
  dg-check/index.html, dg-check/app.js, dg-check/core.js — инструмент 2
  lib/manifest-format.js        — константы формата + validateStructure()
  ```
- **Разделение UI и логики.** `core.js` в каждом инструменте — чистые функции,
  принимающие уже распарсенные книги ExcelJS и примитивные параметры (список
  файлов в нужном порядке, флаг renumber; либо две книги для сверки) и
  возвращающие готовую книгу/сводку. `app.js` — только работа с DOM, вызовом
  `core.js` и скачиванием результата. Так тесты гоняются в Node (ExcelJS работает
  и в Node, и в браузере) без headless-браузера.
- **Сопоставление колонок в сверке — по тексту заголовка**, не по букве столбца:
  ищем в строке заголовков ячейки, содержащие (без учёта регистра) «контейнер» —
  номер контейнера в обоих файлах, «опасн» — колонка «Опасные грузы» в сводном
  файле, «un» — номер UN и «класс» — класс опасности в DG-манифесте. Если что-то
  не найдено — ошибка с указанием, какой заголовок не найден и в каком файле.
- **Сопоставление строк по номеру контейнера** — точное совпадение текста (после
  обрезки пробелов), без учёта регистра.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `lib/manifest-format.js` | описание формата манифеста (лист, строки, колонки) | `validateStructure(workbooks) -> {ok, error?}`, а также именованные константы формата (`SHEET_NAME`, `HEADER_FIRST_ROW`, `COLUMN_HEADER_ROW`, `DATA_START_ROW`, `FIRST_COLUMN`, `LAST_COLUMN`) — переиспользуются в `merge/core.js` и `dg-check/core.js`, чтобы не дублировать номера строк/колонок | сырые обращения к ячейкам без этих констант |
| `merge/core.js` | логика склейки | `mergeManifests(workbooks, {renumber}) -> {resultWorkbook, summary}` | построчное копирование стилей, пересчёт нумерации |
| `dg-check/core.js` | логика сверки | `crossCheckDangerousGoods(combinedWb, dgWb) -> {resultWorkbook, summary}` | поиск колонок по заголовку, группировку по контейнеру, правила подсветки |
| `app.js` (в каждом инструменте) | состояние страницы (выбранные файлы, порядок, чекбоксы) | — (точка входа, ничего не выставляет наружу) | работу с `<input type=file>`, drag-and-drop, скачивание блоба |
| `tools.js` | список карточек главной страницы | массив `{title, description, href}` | — |

Швы для тестов — ровно эти же границы: `validateStructure`, `mergeManifests`,
`crossCheckDangerousGoods`. Каждая — чистая функция от книг ExcelJS и примитивов,
без DOM и без сети; тестируются в Node на реальных `.xlsx`-примерах.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R04 (в части «хранить историю файлов») | пользователь подтвердил: расширяемость — про новые инструменты, не про базу данных; хранение истории — отдельная задача (см. брифинг) |
| Другая раскладка манифеста (не шапка в строках 1–5 / данные с 6-й, колонки не `C:Y`) | сайт рассчитан на подтверждённый шаблон текущих файлов; под новый шаблон формат в `lib/manifest-format.js` потребуется обновить отдельно |
| Файлы весом в десятки тысяч строк | в примерах — до ~1000 строк на файл; обработка в браузере рассчитана на этот порядок, не на промышленные объёмы |
| Сохранение состояния между визитами (выбранные файлы, история результатов) | сайт статический и одноразовый по назначению — обновление страницы сбрасывает прогресс, это осознанно принято ради простоты |
